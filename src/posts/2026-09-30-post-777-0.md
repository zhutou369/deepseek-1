*   **設備調度：** 如何在多船同時靠泊、多輛貨車同時進出的情況下，動態分配設備資源，避免擁堵和閒置。

## 數據準備：優化前的基石

2.  **碼頭設施數據：**

    *   歷史作業時間、效率數據

### 2. Prompt Engineering 核心策略

與 DeepSeek 交互的關鍵在於如何設計清晰、明確且包含足夠上下文的提示詞（prompts）。

*   **定義角色與目標：** 在提示詞中明確 DeepSeek 的角色（例如：「你是一名資深的碼頭調度專家，目標是最大限度提高堆場利用率並減少二次搬運。」）
*   **提供約束與條件：** 說明碼頭的具體規則，例如：
    *   「同目的地的箱子應盡可能堆疊在一起。」
    *   「危險品櫃需放置在指定區域。」
    *   「重箱不應堆疊在輕箱之上。」
    *   「碼頭起重機每次移動應優先處理多個任務，減少空跑。」
*   **輸入數據格式：** 明確告訴 DeepSeek 輸入數據的結構（例如：「以下是當前待處理集裝箱列表（JSON 格式）：...」）
*   **輸出數據格式：** 指定 DeepSeek 的輸出格式，例如要求輸出為 JSON 格式的堆存計畫或設備調度指令。

```json

  "container_id": "CZXU1234567",
  "current_location": "Yard_A_Stack_01_Layer_2",
  "suggested_location": "Yard_B_Stack_05_Layer_1",
  "action_type": "move",
  "reason": "Optimize for vessel XY-Z departure, minimize re-handle."
}
```

*   **分步提問：** 對於複雜問題，將其拆解為一系列小問題，逐步引導 DeepSeek 解決。例如，先優化堆存，再基於堆存結果調度設備。

**目標：** 根據集裝箱的各種屬性（目的地、船期、尺寸、重量），動態推薦最佳堆存位置，最小化二次搬運，並最大化堆場空間利用率。

**DeepSeek 的角色：**
1.  **數據攝取與分析：** 接收來自 TOS 的待堆存集裝箱列表及當前堆場佈局。
2.  **模式識別與預測：** 分析歷史數據，預測未來集裝箱的離港高峰，從而預留出口通道。
3.  **生成優化方案：** 根據設定的規則和約束（例如：按目的地分區、預留通道、避免重箱壓輕箱、同船箱子盡量集中），生成每個集裝箱的推薦堆存位置。

## 成果評估與持續改進

導入 DeepSeek 優化碼頭運營後，需要持續監控和評估其效果，並進行迭代改進：

*   **關鍵績效指標（KPIs）：**
    *   **堆場利用率：** 單位時間內堆場空間的平均佔用率。
    *   **二次搬運率（Re-handle Rate）：** 每個集裝箱在離開堆場前平均被移動的次數，目標是降低此值。
    *   **卡車周轉時間（Truck Turnaround Time）：** 卡車從入閘到出閘的平均時間。
    *   **設備閒置時間：** 各類設備的閒置時長佔總時長的比例。
    *   **吞吐量：** 單位時間內處理的集裝箱數量。
*   **A/B 測試：** 在實際環境中，將 DeepSeek 建議的調度方案與傳統人工方案進行對比，量化效果差異。
*   **反饋循環：** 收集碼頭操作員和調度員的實時反饋，用於調整 DeepSeek 的提示詞、規則和模型行為。
*   **人類介入與監督：** 雖然 DeepSeek 能提供優化建議，但最終的決策和緊急情況處理仍需依賴經驗豐富的人類調度員。AI 應作為決策支持工具，而非完全取代人工。
